# TMT Atlas｜评测方案与当前结果

## 1. 评测原则

TMT Atlas 的质量不能只用“回答是否流畅”衡量。金融研究工作台至少要同时评估数值正确性、来源可追溯性、口径安全、模型忠实度、降级能力和用户是否知道下一步做什么。

当前项目仍处于本地 MVP 阶段，因此本文件区分：

- **已运行结果：** 当前代码和固定演示数据可以验证的事实。
- **目标指标：** 后续接入真实材料和用户测试后才可以报告的目标。
- **未验证项：** 不应在简历或面试中写成已实现成果。

## 2. 当前已运行的核心测试

运行命令：

```bash
python3 -m unittest discover -s tests -v
```

当前最后一次完整本地运行记录为 82 项通过；如果新增数据、环境或依赖，应在发布前重新运行并以实际输出为准。

- 演示工作区至少包含 9 家跨市场 TMT 公司和 3 个研究方向。
- 公司快照保留来源 ID、来源 URL 和“演示归一化值”状态。
- 赛道扫描输出收入、增速、毛利率、营业利润率、研发费用率和资本开支字段，并保留可比性提醒。
- 事件分析将直接事实、传导路径、推断和待验证问题分开输出。
- 本地 PDF/CSV/JSON/Markdown/TXT 导入保留证据定位；CSV 事实只生成 pending 提案。
- SQLite 工作区保留来源、证据、事实审核状态和审计记录，事实不会自动批准。
- 金融引擎覆盖增长率、利润率、CAGR、单位转换、FCF、企业价值、估值倍数、DCF 和可比性边界。
- 授权 RSS/Atom/JSON Feed 收集器默认关闭，测试了授权、去重、私网阻断、重定向阻断和审核箱。
- 搜索可以返回公司、事件和来源。
- 备忘录在不接 LLM 的情况下可以生成 Markdown 和 HTML。
- 用户新增来源会在本地保存并按标题+URL 去重。

## 3. 最小评测集设计

### 3.1 数据边界

演示数据集不代表实时市场数据。`data/demo_seed.json` 的 `dataset.status` 为 `illustrative_demo`，所有指标带有 `status: demo`。因此当前测试验证的是产品流程和数据边界，而不是对真实财报数字的事实准确率背书。

### 3.2 计算用例

当前已由 `tests/test_finance.py` 覆盖核心黄金用例：

| 用例 | 期望行为 |
|---|---|
| 正常同比增长 | 按公式计算，并保留分子、分母和期间 |
| 上年值为 0 | 不计算，显示原因 |
| 本期缺失 | 不填 0，显示未披露/待补充 |
| 单位为 USD million 与 USD billion | 只有在单位族一致时转换 |
| 币种不同 | 不自动换算，除非有汇率来源和日期 |
| 财年截止日不同 | 显示不可直接比较提醒 |
| 业务范围不同 | 不进入默认排名 |
| 负收入或异常分母 | 触发异常值警告 |
| GAAP 与非 GAAP | 分开存储和展示 |
| 四舍五入 | 内部保留精度，展示层再处理 |

### 3.3 引用与证据用例

当前已由 `tests/test_evidence.py` 与 `tests/test_integration.py` 覆盖基础行为：
| 用例 | 期望行为 |
|---|---|
| 有页码/段落的事实 | 可以点击来源并定位 |
| 只有来源首页 | 标记为来源入口，不能冒充段落证据 |
| 无来源数字 | 不允许进入已确认结论 |
| 两个来源冲突 | 展示双方，不自动裁决 |
| 用户删除来源 | 相关结论变成需补证据 |
| 模型无答案 | 明确“不足以判断”，不能补全 |

### 3.4 LLM 用例

接入 OpenAI-compatible API 后，加入固定测试集：

- 证据中有答案，模型正确引用。
- 证据中无答案，模型拒答。
- 证据包含两个期间，模型不混淆期间。
- 证据只披露增速，模型不推出绝对金额。
- 证据包含相反表述，模型列出冲突。
- 用户选中的证据不足 12 条时正常请求。
- API 超时/返回错误时 UI 仍可回到本地备忘录。
- API key 不出现在日志、响应和导出文件。

## 4. 用户体验评测

邀请 2—5 名同学或同事完成以下任务：

1. 启动服务并进入首页。
2. 找到 NVIDIA 公司快照。
3. 解释一个指标的来源和数据状态。
4. 比较一个赛道中的公司。
5. 分析一条事件，并指出待验证问题。
6. 生成并下载一份研究备忘录。
7. 找到 LLM 开关并说明默认为什么关闭。

记录：首次成功时间、任务完成率、误点击、用户主动提问、无法理解的标签、对“演示数据”提示的理解程度，以及用户是否能复述产品价值。

## 5. 目标指标（尚未声称实现）

- 核心金融公式测试通过率：100%。
- 有效输入下来源定位成功率：≥95%。
- 关键事实引用覆盖率：≥95%，正式导出目标 100%。
- 无证据时拒答/转人工率：≥95%。
- 无 LLM 模式核心任务完成率：100%。
- 从打开示例工作区到导出首份备忘录：≤10 分钟。
- 关键 UI 流程自动化覆盖导入、审核、计算和导出。

这些目标只有在真实材料、测试记录和用户试用完成后才能写入项目结果或简历。

## 6. 失败案例（当前产品主动展示）

### 失败案例 A：演示数字看起来像真实财报

问题：如果界面只展示“收入 130.5bn”，用户可能误以为这是已核验的实时事实。

处理：数据集加入 `illustrative_demo` 状态；指标卡显示“演示归一化值”；页面顶部显示数据边界；来源页保存官方入口而非伪造页码；README 明确禁止将演示数据用于投资决策。

### 失败案例 B：事件标题被误解成投资结论

问题：一个“AI 资本开支更新”不能直接推出利润率或股价方向。

处理：事件页拆成直接事实、传导路径、分析性推断和待验证问题；证据覆盖为 0 的演示事件不会被包装成已确认结论。

### 失败案例 C：实时资讯自动写入事实层

问题：自动收集可能遇到重复公告、错误日期、非官方转载和模型误读。

处理：当前只生成 review-first 计划；新内容进入待审核资讯箱；用户确认后才进入事实抽取流程。

## 8. 目前不应宣称的结果

当前没有外部用户规模、留存、真实研究效率提升、投资收益、生产级实时数据覆盖、商业 API 服务等级或金融决策准确率证据。因此简历和面试中应使用“完成了本地可运行 MVP”“建立了可复核的评测框架”“实现了无 LLM 核心路径”等可验证表述，而不应写“提升研究效率 X%”“准确率 X%”或“支持实时全市场数据”。
