# TMT Atlas｜产品概览与使用手册

## 1. 产品是什么

TMT Atlas 是一个专注于科技、媒体与电信行业研究的本地优先工作台。它把研究人员通常分散在年报、公告、IR 页面、表格和笔记里的信息，组织为来源、证据、事实、计算、事件和研究备忘录。

它的目标不是自动做出买入或卖出判断，而是减少研究中重复整理和口径混乱的工作，让用户更快得到一个可以复核、可以继续讨论、可以导出的研究草稿。

产品的主线是：

> 来源 → 证据 → 事实 → 计算 → 推断 → 人工审阅 → 备忘录

## 2. 适合谁

它适合金融研究/投研实习生、行业研究员、企业战略或投资团队，也适合作为 AI 产品经理候选人的完整作品集。前两类用户关注研究效率和金融口径，后者关注用户问题、Agent 工作流、模型边界、评测、隐私和产品迭代。

## 3. 如何开始

进入项目目录并执行：

```bash
python3 server.py
```

打开 `http://127.0.0.1:8765`。无需数据库服务、无需 Docker、无需 LLM API key。

## 4. 四条主要工作流

### 公司快照

在“公司快照”中选择 NVIDIA、Microsoft、阿里巴巴、百度等公司。页面会显示公司身份、行业、收入、收入增速、毛利率、营业利润率、研发费用率、资本开支和分部/用户代理指标。每个指标旁边都显示数据状态和来源入口。

使用时不要只看大数字。优先检查报告期、单位、币种、会计准则和来源。正式使用时，需要把演示归一化值替换为官方文件中的原始事实，并记录页码或段落。

### 赛道扫描

在“赛道扫描”中选择 AI 基础设施/半导体、云/SaaS 或平台/电商/广告。系统生成公司×指标矩阵，并按收入增速展示演示排序。

这个页面的重点不是自动给公司打分，而是提示比较条件：不同财年能否对齐，指标是否同名同义，分部范围是否一致，是否混用了 GAAP/IFRS 和管理层非 GAAP 指标。如果不确定，界面标记“需审核”，而不是把结果包装成确定结论。

### 事件雷达

在“事件雷达”中选择公告、业绩或监管事件。页面将事件拆成直接事实、可能传导路径、分析性推断和待验证问题。

这是产品最适合展示“金融分析 + Agent 边界”的页面。系统不会因为一个事件标题就自动推导收益或投资结论，而是提醒用户验证事件规模、受影响业务、时间窗口、反向证据和管理层澄清。

### 研究备忘录

在“研究备忘录”中选择公司、赛道和事件，输入研究员备注，点击生成。系统会用本地模板整合已选对象，并生成 Markdown 和 HTML 两种格式。文档会保留数据截至时间、演示状态、来源列表和研究边界。

导出后仍然需要人工审阅。尤其要检查是否把演示数据当成真实数据，是否每个关键数字都能定位到官方文件，是否把推断写成了事实。

## 5. 来源与设置

“来源与设置”包含官方来源注册表。当前示例包含公司 IR、SEC EDGAR、HKEXnews 和 SSE 公告入口。产品保存的是来源元数据和链接，不默认复制完整报告。

你可以在此添加自己有权使用的来源。添加时建议记录来源标题、URL、访问权限、核查日期和限制。不要把实习单位内部材料、带个人信息的文件或受限制的商业数据库文件上传到公开 GitHub。

## 6. LLM 设置

LLM 是可选增强，不是产品的前置条件。开启前，用户需要明确填写 Base URL、模型名，并勾选允许发送选定证据片段。API key 通过启动服务的终端环境变量 `TMT_LLM_API_KEY` 提供，程序不会将其写入本地设置。

LLM 最适合做受控的证据摘要、草稿表达和用户选定片段的语言整理。当前实现的是用户明确同意后的选定证据草稿入口；自然语言任务解析、结构化抽取草稿、矛盾解释和事件影响链仍属于后续增强。它不应该负责收入增速、利润率、单位换算或可比公司排名等确定性计算。

当前设计默认只发送用户选中的证据片段，每次最多 12 条；没有开启、没有配置 API key、服务不可用或超时，系统都应保留本地工作流。

## 7. 定期资讯收集

连接 API 后，可以为官方 IR、SEC/EDGAR、HKEX/SSE 或合法新闻源配置定期收集。当前版本支持显式授权后的 RSS/Atom/JSON Feed 元数据收集，并把标题、日期和链接放入审核箱；不会默认执行全网爬取或自动写入事实。

推荐流程是：收集元数据、去重、按日期和主题分类、进入待审核资讯箱、用户确认后再抽取事实。这样可以防止新内容未经审阅就改变可信事实层。

## 8. 数据字段的含义

每个指标至少需要主体、指标名、值、单位、币种、期间、来源、状态和定位信息。当前事实状态主要包括演示归一化值、pending、accepted、rejected、缺失/未披露和冲突；“已核验”事实存放在单独的官方事实语料中。

缺失值不等于零。一个公司没有披露某指标，不能在比较表里自动填 0。一个公司披露“云收入增长 25%”，也不能在没有基期收入的情况下推出云收入绝对值。

## 9. 当前演示数据的正确使用方式

当前 `data/demo_seed.json` 的数字用于验证页面、API、报告和测试流程，已在数据集里明确标记为 `illustrative_demo`。它们不是截至日期的实时市场数据，也不能用于交易或投资决策。

正式增加真实数字时，建议每个事实都补充：文件标题、发布日期、报告期、页码/段落、原始单位、是否 GAAP/IFRS、是否管理层指标、抽取方式和核查人。

## 10. 一个研究员的实际使用示例

问题：我要快速了解一家云业务公司的 AI 投入是否正在改变经营表现。

第一步，进入公司快照，选择 Microsoft 或阿里巴巴，确认收入、营业利润率、资本开支和云业务占比。

第二步，进入赛道扫描，把公司放到云/SaaS 组中，检查同业的财年和分部口径是否可比。

第三步，进入事件雷达，选择与业绩或 AI 投入有关的事件，查看直接事实与待验证问题。

第四步，进入研究备忘录，选择公司、赛道和事件，写下研究员的重点问题，生成本地草稿。

第五步，回到官方文件核验数字，再把“已验证事实”和“待验证推断”分开呈现。

## 11. 这个产品为什么不默认做自动荐股

金融研究中，来源、期间、口径和因果关系都需要审阅。将一个模型输出直接变成投资建议，会隐藏数据缺口和不确定性，也不能体现专业研究流程。TMT Atlas 把产品目标放在证据组织和判断辅助上，保留人的研究责任和决策权。
