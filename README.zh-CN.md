# TMT Atlas Agent

**面向 TMT 行业研究员的本地优先研究工作台。它把一项研究从一条资讯推进到一份带出处的备忘录，并让每个数字都能回到官方披露。**

[English](README.md) | 简体中文

TMT Atlas Agent 不是自动交易系统，不是投资顾问，不是实时行情终端，也不是会自己批准事实的自主研究员。结论由研究员来写。

## 研究链路

应用的主要页面对应同一条链路上的六步。下表是一项研究的走法，顺序与演示时一致；侧边栏的分组不同，授权收集放在“本地研究工具”下面。

| 步骤 | 应用里的页面 | 你做什么 | 产品保证什么 |
|---|---|---|---|
| 1. 资讯收集 | 授权收集 | 填入你有权读取的 Feed，勾选授权，运行一次 | 只访问这个 Feed。只保存标题、日期和链接。每条先标 `pending`，不会自己变成财务事实。 |
| 2. 赛道扫描 | 赛道扫描 | 选一个赛道 | 币种、报告期、会计准则、合并范围和单位都一致的公司才进入同一个排名，其余标“不可比较”。不做汇率换算。 |
| 3. 事件雷达 | 事件雷达 | 打开一条事件 | 直接事实、传导路径、推断和待验证问题分开写。推断标注“必须人工确认”。 |
| 4. 公司快照 | 公司快照 | 选一家公司 | 每个指标是 `direct`（直接披露）、`derived`（公式计算，显示公式和输入）或 `missing`（未披露，写明原因）。 |
| 5. 研究备忘录 | 研究备忘录 | 选快照、赛道和事件，写备注 | 事实带报告期和来源，缺的写“未披露”。可导出 Markdown 或 HTML。 |
| 6. 研究判断 | 备忘录里的“研究结论” | 你自己写 | 产品不给评级，不给买卖建议。 |

链路旁边还有三个页面，见[功能详解](#功能详解)：

- 证据审核：把你自己的 PDF、CSV、JSON、Markdown 或文本文件变成带定位的证据，并审核提出的事实。
- 金融计算：增速、利润率、CAGR、单位换算、估值倍数、自由现金流和简化 DCF，输入和公式都可见。
- Agent 自动化：批准一次计划，就可以让它刷新快照、做赛道扫描、分诊事件、起草备忘录或收集授权资讯。结果一律是草稿。

## 十分钟走完整条链路

先启动服务（见[本地运行](#本地运行)），打开 <http://127.0.0.1:8765>，然后按六步操作。下面的数字来自仓库自带的官方事实库，可以和你屏幕上的对照。

1. **资讯收集。** 打开“授权收集”，填入 `https://nvidianews.nvidia.com/releases.xml`，勾选两个复选框（启用定期收集；确认已获得来源授权），点“保存授权配置”，再点“现在运行一次”。审核箱里会出现英伟达新闻中心的 `pending` 条目。条数取决于你运行当天的 Feed。
2. **赛道扫描。** 打开“赛道扫描”，选“平台/电商/广告”。Meta（22.2%）、Alphabet（15.1%）、Amazon（12.4%）依次排第 1 到 3，因为三家都以美元、2025 日历年、US GAAP、合并报表披露。腾讯（13.9%）以人民币和 IFRS 披露，留在表里标“不可比较”，不编号。
3. **事件雷达。** 打开“事件雷达”，选“出口管制与供应链风险”（英伟达）。传导路径直接引用快照里的数字：收入增速 114.2%、资本开支 3,236 百万美元、营业利润率 62.4%，并提醒不能只凭标题判断利润率的方向。
4. **公司快照。** 打开“公司快照”，选英伟达。总收入 130,497 百万美元（FY2025，US GAAP，`direct`）。收入增速 114.2% 是 `derived`，卡片上写着公式 (130,497 − 60,922) ÷ 60,922。研发费用率是 `missing`，原因写在卡片上。
5. **研究备忘录。** 打开“研究备忘录”，在三个下拉框里选英伟达、平台/电商/广告和这条出口管制事件，点“生成本地备忘录”。想让自己的判断出现在“研究结论”下面，先在“研究员备注”里写。
6. **研究判断。** 读完备忘录，判断出口管制对英伟达增速意味着什么，写进结论。产品里没有任何环节替你做这件事。

想看 Agent 这一层：打开“Agent 自动化”，为英伟达新建一个“公司快照刷新”计划，批准，点“立即运行”。结果出现在“研究草稿产物”里，是标着“facts approved：否”的草稿。

## 功能详解

### 1. 授权资讯收集

- 支持 RSS、Atom 和 JSON Feed 地址。只允许 HTTPS 和公网主机；内网或本机地址、带账号密码的地址、带跳转参数的地址都会被拒绝。
- 默认关闭。你启用收集并勾选授权之前，不会访问任何地址。最小间隔 15 分钟，定时器只在本地服务运行时工作。
- 每条只保存标题、日期、链接和来源名称，不保存正文。
- 每条先进入审核箱，状态 `pending`。点“进入研究线索”标为 `accepted`，点“忽略”标为 `rejected`。两种操作都不会改变 `facts_approved`，它始终是 `false`：一条资讯是给研究员的线索，不是事实。

### 2. 赛道扫描

扫描覆盖三个赛道：AI 基础设施/半导体（英伟达、中芯国际）、云/SaaS（微软、阿里巴巴、百度）、平台/电商/广告（亚马逊、Alphabet、Meta、腾讯）。表里列出收入、收入增速、毛利率、营业利润率、研发费用率、资本开支和可比性标签。

排名规则故意定得很严。公司按币种、报告期、期间类型、基础会计准则、合并范围和单位分组。同一组有两家及以上，就按收入增速排名；一家公司单独成组，标“不可比较”；没有增速数据的标缺失。“未披露”不当作零，也不做任何币种换算。

目前只有平台赛道形成排名组（三家美国公司）。另外两个赛道里的公司财年截止日或会计口径各不相同，所以不出排名。这是预期行为，不是数据缺口。

### 3. 事件雷达

每条事件拆成四块：

- **直接事实：** 主体、日期、事件类型和来源状态，只写来源能确认的内容。
- **可能的传导路径：** 直接引用公司快照里的数字（收入增速、资本开支、营业利润率），并写明还需要确认什么。
- **分析性推断：** 单独成栏，标注“必须人工确认”。
- **待验证问题：** 比如受影响业务的绝对规模有没有披露。

应用自带的十条事件是示例，带“演示事件”标记，证据覆盖率显示 0%，避免被当成有来源的新闻。

### 4. 公司快照

每家公司有 10 到 12 张指标卡，数量取决于公司披露了什么。核心指标是总收入、收入增速、毛利率、营业利润率、研发费用率、资本开支、核心业务占比和营业利润；有数据时还有经营现金流、净利润和分部收入。每张卡有三种状态之一：

| 状态 | 标签 | 含义 |
|---|---|---|
| `direct` | 官方直接披露 | 直接取自官方披露，写明报告期、币种、会计准则、来源标题，以及出自哪张表哪一行 |
| `derived` | 官方事实派生 | 由官方事实计算得出，卡片上印出公式和输入 |
| `missing` | 未披露 | 没有同口径的官方事实，卡片写明原因，不做估算 |

快照页的“加入研究备忘录”按钮会跳到备忘录构建器。

### 5. 研究备忘录

备忘录构建器接收可选的公司快照、赛道和事件，加上你的备注，生成一份草稿，章节顺序如下：

1. 研究结论：你写的备注。没写就只显示一行提示，系统不替你下结论。
2. 关键事实与计算：每个指标一行，带报告期、状态和来源标题；缺失的写“未披露”并给出原因。选了赛道和事件的话，赛道比较与事件分析作为小节接在后面，事件分析列出直接事实和待验证问题。
3. 研究边界和来源，来源带链接。

结果可以导出为 Markdown 或 HTML。备忘录由模板生成，不需要任何语言模型。

### 6. 证据审核

对于你自己带来的材料，这个页面保留从文件到事实的完整链条：

- 导入本地 PDF、CSV、JSON、Markdown 或文本文件。每个片段都保留位置：PDF 记页码，文本记行号，CSV 记行号。解析 PDF 需要可选依赖 `pdfplumber` 或 `pypdfium2`，扫描件可以使用可选的本地 OCR。
- 搜索片段，再从片段提出一条事实。提出的事实起始状态是 `pending`。
- 接受或拒绝一条事实，必须写理由。同一指标上有两条互相矛盾的事实时，会标“需核验”，不会让其中一条悄悄覆盖另一条。
- 来源、证据、事实和每次审核决定都存在本地 SQLite 文件里，形成审计记录。

### 7. 金融计算

所有运算都由普通 Python 代码完成，输入、公式和警告都可见。它不替你猜：分母为零、数值缺失或单位不匹配时，会拦截结果并说明原因；负收入这类异常值会给出警告。

支持的运算：增速、利润率、CAGR、单位换算、可比性检查、企业价值、EV/收入、市盈率、自由现金流，以及带敏感性表和情景的简化 DCF。

### 8. Agent 自动化

Agent 计划是你批准一次的研究任务，共五类：

| 类型 | 一次运行产出什么 |
|---|---|
| `company_snapshot_refresh` | 一家公司的快照草稿，由官方事实构建 |
| `sector_scan` | 一个赛道的扫描草稿，含可比性结果 |
| `event_triage` | 一条事件的拆解草稿 |
| `memo_draft` | 基于公司、赛道或事件的备忘录草稿 |
| `collection_cycle` | 从你列出并授权的 Feed 取回的新条目，等待审核 |

计划的流程是 `draft → approved → 按计划或手动运行 → 草稿产物或审核门`。间隔至少 15 分钟，计划可以暂停和恢复，调度器只在本地服务运行时工作。每份产物在你接受或拒绝（必须写理由）之前保持“待确认”，接受草稿也不会批准任何财务事实。资讯收集计划只会访问自己范围里列出的 Feed。

### 9. 可选的语言模型

语言模型默认关闭，上面整条链路都不需要它。打开后，它可以把你选定的证据写成一段草稿：

- 需要打开设置，并在每次请求时再次确认。API Key 只从环境变量 `TMT_LLM_API_KEY` 读取，不会写入磁盘。
- 它只收到你勾选的证据，最多 12 条，不收到别的东西。
- 回答里的每条论断都必须引用已发送证据的编号。出现新数字、新日期或不存在的引用，整段回答被拒收。
- 结果只是草稿，不能写入或批准事实。模型不可用时，规则生成的结果保持原样。
- 内网地址会被拒绝。本地 Ollama 需要显式设置 `allow_local_llm`。

## 数据模型

仓库自带的语料是 `data/official_facts.json`：9 家公司（NVIDIA、中芯国际、Microsoft、Alibaba、Baidu、Amazon、Alphabet、Meta、Tencent）共 60 条事实，取自业绩公告、10-K 和 6-K 文件、投资者关系页面和发行人公告。每条事实记录公司、指标、数值、用到时的上期数值、单位、币种、报告期、会计准则、范围、来源链接、来源标题、发布日期，以及出自哪张表哪一行的定位。

三条规则决定了页面上显示的一切：

- 一个值只能是 `direct`、`derived` 或 `missing`，没有第四种“估算”。
- 派生值只会用币种、报告期、会计准则、范围和单位都一致的事实来算。
- 公开页面只放链接，不复制全文。仓库保存结构化事实和来源链接，不保存受限制的完整报告。

页面上的数字来自 `official_facts.json`。`data/demo_seed.json` 只放公司元数据、十条示例事件和示例提问。

## 本地运行

环境要求：Python 3.10 及以上。核心只用标准库，不需要 Docker、Node 或数据库服务，也不需要 API Key。

```bash
git clone https://github.com/Rafaaa13/tmt-atlas-agent.git
cd tmt-atlas-agent
python3 server.py
```

打开 <http://127.0.0.1:8765>。运行测试：

```bash
python3 -m unittest discover -s tests -v
```

当前基线是 **152 项测试通过**。

| 环境变量 | 作用 | 默认值 |
|---|---|---|
| `TMT_HOST` | 服务绑定的地址 | `127.0.0.1` |
| `TMT_PORT` | 端口 | `8765` |
| `TMT_LLM_API_KEY` | 可选语言模型的 Key | 空 |
| `TMT_LLM_BASE_URL`、`TMT_LLM_MODEL` | 可选语言模型的地址和模型名 | 空 |

**安全提示：** 服务没有登录功能，默认只绑定 `127.0.0.1`，只有你自己的电脑能访问。没有先加上身份验证之前，不要把 `TMT_HOST` 设成公网地址，也不要把服务放在公网端口后面。

## 接口概览

所有路由都是 `server.py` 提供的本地 JSON 接口。

| 领域 | 路由 |
|---|---|
| 研究视图 | `GET /api/companies/{id}/snapshot`、`GET /api/sectors/{sector}`、`GET /api/events`、`GET /api/events/{id}`、`POST /api/memos` |
| 证据与事实 | `POST /api/ingest`、`GET /api/evidence`、`GET /api/facts`、`POST /api/facts`、`POST /api/facts/review`、`GET /api/audit` |
| 计算 | `POST /api/calculate` |
| 资讯收集 | `POST /api/collection/config`、`POST /api/collection/run`、`GET /api/collection/inbox`、`POST /api/collection/review` |
| Agent | `GET/POST /api/agent/plans`、`POST /api/agent/plans/{id}/approve`、`.../pause`、`.../resume`、`.../run`、`GET /api/agent/runs`、`GET /api/agent/artifacts`、`POST /api/agent/artifacts/{id}/review`、`GET /api/agent/review-gates`、`GET /api/agent/retrieval-items` |
| 语言模型 | `POST /api/settings/llm`、`POST /api/llm/enhance`、`POST /api/llm/draft`（旧路由） |

```text

evidence_engine.py        # 本地文件导入与带定位的证据
workspace_db.py           # 来源、证据、事实、审计的 SQLite 存储

data/demo_seed.json       # 公司元数据、示例事件、示例提问
frontend/                 # 工作台页面
tests/                    # 152 项测试
docs/                     # 架构、产品、评测和面试说明
```

## 当前限制

- 数据是已披露的历史数据，不是实时行情，也不会自动刷新。
- 事件雷达里的十条事件是示例。从资讯审核箱“进入研究线索”的条目会被标为 `accepted`，但目前还没有任何环节把它们带进事件雷达。把两者接起来，是这条链路的下一步。
- 资讯收集和 Agent 调度器都只在本地服务运行时工作。
- 赛道扫描设计得很严，多数赛道里排名的公司很少甚至没有。跨币种比较需要带日期、带来源的汇率，产品目前不使用汇率。
- 产品不给评级、目标价或交易信号。
- 仓库不附带完整财报。公开页面只放链接；你添加的文件或 Feed，需要自己确认有权读取和处理。
