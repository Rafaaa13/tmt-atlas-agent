01 / WHY

我解决的不是“不会问”，而是“无法复核”。

TMT 研究的麻烦常常不在某个公式，而在材料分散、指标口径不一致，以及一段看起来很对的文字无法回到原始证据。

01材料分散

年报、业绩公告、IR 新闻、表格和研究笔记分散在不同位置，研究员花时间搬运信息，而不是识别变化。

02数字不可比

财年、币种、会计准则、合并范围和分部定义稍有差异，排名就可能把不同东西放在一起。

03AI 很流畅，但不一定可信

模型可以给出完整的解释，却可能混淆报告期、把缺失值补成零，或者把推断写成事实。

04研究经验难以复制

资深研究员知道先找什么、哪些数字不能混算；新人需要一条清楚的路径，而不是一个更大的聊天窗口。

03 / BUILD

AI 放在该放的位置。

技术与产品结构

数据层官方历史事实 JSON + SQLite 证据/事实/审计工作区；缺失值保持缺失。
规则层OfficialSnapshotBuilder、可比性检查、金融计算引擎；输入、公式和警告可回放。
Agent 层计划 → 运行 → 任务 → 审核门 → 草稿产物；授权 Feed 只按 scoped source 运行。
表达层OpenAI-compatible LLM 可选；只接收选定 evidence，结构化引用校验后仍标为 draft。

一个关键取舍

我没有让模型负责收入增速、利润率或横向排名。原因很简单：这些输出一旦错了，流畅的语言反而会让错误更难被发现。

  • 没有 LLM：快照、计算、证据审核和模板备忘录仍可运行。
  • 有 LLM：只做选定证据的语言草稿，不写入事实。
  • 有定时任务：只访问被批准的来源，结果先进入审核箱。
  • 有冲突或缺失：页面明确显示，而不是用一个分数掩盖。

05 / STORY

面试时，我会这样讲。

SITUATION
TMT 研究材料分散，关键指标的期间、币种和合并范围经常不一致；通用聊天机器人又很难说明一段判断到底依据了什么。
TASK
做一个既能体现金融研究专业性、又能体现 AI 产品能力的工作台：让研究从来源出发，经过审核、计算和比较，最后形成可解释的备忘录。
ACTION
我建立了官方事实层、证据审核层和确定性金融引擎，再把 Agent 设计成可批准的计划，而不是自由浏览。LLM 只负责被选择证据的语言增强。
RESULT
完成了 9 家公司的官方历史事实模式、5 类 Agent 计划、证据导入、可比性检查和研究草稿产物，并用 151 项本地测试验证了主要边界。真实用户效率和留存仍留在下一阶段验证，不把目标写成结果。
06 / BOUNDARIES

我会主动说清楚它还不能做什么。

不是实时行情终端

当前是官方历史事实工作区；RSS/Atom/JSON Feed 只保存授权来源的资讯元数据，不承诺全市场实时覆盖。

不是自动投资建议

它能整理事实、计算口径、呈现比较和问题，但不输出买卖建议、收益承诺或自动下单。

不是无监督多 Agent

Agent 可以定时运行和产出草稿，但每一个会改变研究状态的环节都需要人工审核门。

公开不等于可再分发

仓库保存结构化事实和来源链接，不复制完整受限报告；真实材料仍由使用者承担权限核验责任。

一个适合金融科技岗位的项目，应该让人看见判断边界。

TMT Atlas Agent 的核心不是“让 AI 做更多”，而是让 AI 在可信的来源、规则和审核边界内做得更好。
